Visible DMA heaps included system, system-uncached, mtk_mm, mtk_mm-uncached, protected page/region heaps, SVP, and TEE heaps. Listing a heap does not prove that Termux can allocate from it or that it is available to the GPU/NPU.

The Android thermald and mi_thermald services report running. Thermal sysfs sensor data was not readable in the captured Termux context.

## Android access boundary

The Termux process identified itself as UID 10250 in SELinux domain untrusted_app_27.

- /dev/dri/card0 exists as major 226, minor 0, owned by system:system, mode 0660, label dri_device.
- Termux is not in the system group.
- /sys/class/drm returned Permission denied.
- Direct inspection of hwcomposer.mtk_common.so returned Permission denied.

Empty results from restricted sysfs paths or module directories are therefore not evidence that the hardware or driver is absent. No permission changes, root actions, or vendor modifications were made.

## Vulkan validation already completed

On the reference device:

- **R1.1:** physical-device discovery and capability/feature/limit queries passed for Mali-G925-Immortalis MC12; device API 1.3.278.
- **R1.2:** logical device creation and graphics queue retrieval passed; cleanup passed.
- **R1.3:** an intentionally empty primary command buffer was submitted; queue submission returned VK_SUCCESS, fence wait/status succeeded, and Vulkan object cleanup succeeded.

R1.3 proves command submission and fence completion for an empty command buffer. It does not prove graphics rendering, surface/swapchain presentation, DXVK compatibility, a game workload, sustained performance, or FPS.
